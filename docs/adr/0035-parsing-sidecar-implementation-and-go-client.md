# ADR-0035: Parsing sidecar implementation and Go client — Flask + focused per-format libraries, shared Normalised contract, retrying traced client

**Status:** Accepted · **Date:** 2026-09-03 · **Requirements:** FR-ING-11, FR-SRC-02, SPEC-05 §2, SPEC-05 §8, NFR-MNT-01 · **Decisions:** ADR-0006, ADR-0034

## Context
ADR-0006 decided a stateless Python sidecar parses the heavy formats
(PDF/DOCX/PPTX/XLSX) the Go parsers cannot, over `POST /parse`. STORY-01.2 landed
a dependency-free health-only stub; STORY-05.3 makes it real and adds the Go
client. The Go native parsers (STORY-05.2, ADR-0034) already emit
`Normalised{Title, Blocks}`; the sidecar and its client must produce and consume
the *same* shape so both halves feed one chunker (SPEC-05 §3, NFR-MNT-01).

## Options
- **Extraction library.** (a) one unifying extractor — Docling or Unstructured —
  rejected: a large dependency tree and slow, heavyweight image for four formats
  we can cover precisely; failure modes are opaque. (b) **focused per-format
  libraries** (chosen): PyMuPDF (PDF), python-docx (DOCX), python-pptx (PPTX),
  openpyxl (XLSX). Each is small, well-maintained, ships manylinux wheels (no apt
  build toolchain in the image), and fails in an isolated, legible way. The
  interface stays swappable (ADR-0006) — Docling can replace one extractor later
  without touching the worker.
- **HTTP framework.** The stub used stdlib `http.server`, but a real `POST /parse`
  needs correct multipart parsing and a body-size limit at a trust boundary. (a)
  hand-rolled multipart on stdlib — rejected: fiddly, easy to get wrong on exactly
  the untrusted input. (b) **Flask + gunicorn** (chosen): `request.files`,
  `MAX_CONTENT_LENGTH` (413 on oversize) and routing are correct and tiny; gunicorn
  is the boring production WSGI server. Sync per-worker because extraction is
  CPU-bound — scale by process/replica, not async.
- **Block shape: `rows` vs ADR-0006's `table`.** ADR-0006 sketched
  `blocks:[{type, level, text, table}]`; SPEC-05 §2 and the Go `parse.Block`
  settled on `rows` (structured cells) plus a GFM markdown `text`. The sidecar
  follows **SPEC-05 §2 (`rows`)** so its JSON decodes straight into
  `parse.Normalised`; the sidecar's `markdown_table` mirrors the Go `markdownTable`
  byte-for-byte so a table hashes identically whichever producer parsed it. ADR-0006
  predates that refinement; this ADR records the reconciliation.
- **Error taxonomy (how the worker should react).** `415` unsupported MIME (the
  worker mis-routed — terminal), `422` parse failure (the worker records
  `metadata.parse_error` and skips the document, the sync still succeeds — SPEC-05
  §2/§8 — terminal), `429`/`5xx` transient (retryable), `413` body too large. The
  Go client maps 415→`ErrUnsupportedFormat`, 422→`ErrParseFailed` (both terminal,
  never retried) and treats 429/5xx/transport errors as retryable.
- **Client resilience & tracing.** The client applies the SPEC-05 §2 120 s parse
  budget as the HTTP client timeout, retries transient failures with capped
  exponential backoff that honours `Retry-After` (delta-seconds or HTTP-date), and
  cancels a pending backoff when the context is done. It wraps each call in an
  OpenTelemetry span and injects W3C trace context into the outbound request using
  the already-installed global propagator (`obs.SetupTracing`, STORY-01.6) — **no
  `otelhttp` dependency** for ~10 lines of propagation.
- **Client placement.** `internal/ingest/sidecar` — a sibling of
  `internal/ingest/parse`, importing it for the `Normalised` type. The
  `parse.Registry` returns `parse.ErrUnsupportedMIME` for exactly the sidecar
  formats; the sink (STORY-05.6) routes that sentinel to this client.

## Decision
Implement `services/parser` as a Flask app (`app.py`) over pure per-format
extractors (`parsers.py`) returning `{title, blocks:[{type, level?, text?,
rows?}]}`, served by gunicorn (`Dockerfile`), with `GET /healthz` and `POST
/parse` (multipart `file` + `mime`). Add `internal/ingest/sidecar.Client` with
`Parse(ctx, filename, mime, data) (parse.Normalised, error)` and `Healthz`,
carrying the timeout/retry/backoff/tracing above and the terminal-error sentinels.
Add `config.ParserURL` (`PARSER_URL`; compose already sets `http://parser:8081`).
Fixtures for six documents across the four formats are generated by
`gen_fixtures.py` (runtime deps only) and committed under
`services/parser/testdata`.

## Consequences
- The worker (STORY-05.6) parses HTML/MD/text/CSV/JSON in-process and routes the
  four heavy formats to one traced, retrying client, decoding into the same
  `Normalised` — the two producers are interchangeable to the chunker (NFR-MNT-01).
- **Ceiling (ponytail):** PDF heading detection is font-size ranking and PDF tables
  are appended per page (best-effort via `find_tables`), so a PDF heading may be
  mis-levelled or a table slightly out of order — never lost. DOCX/PPTX/XLSX
  headings and tables are deterministic. Upgrade path: Docling/Unstructured behind
  the same `/parse` contract.
- The image adds the four parsing libraries (all manylinux wheels) + Flask +
  gunicorn; it stays a small `python:3.11-slim`, non-root, with the existing
  compose healthcheck against `/healthz` unchanged.
- Tests: `services/parser` pytest (fixtures + HTTP contract, `mise run
  test-parser`, wired into CI) and `internal/ingest/sidecar` Go tests (httptest:
  success/decoding, 415/422 terminal, retry-then-succeed, give-up, Retry-After cut
  short by context, trace-context injection, health). No schema/migration change.
