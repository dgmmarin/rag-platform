# ADR-0029: Sources endpoints — a control-plane store, a 409-by-index concurrent-sync guard, and connector/worker seams

**Status:** Accepted · **Date:** 2026-09-03 · **Requirements:** FR-SRC-01, FR-SRC-14, FR-ACC-03, C-3, C-4, SPEC-07 §2, SPEC-04 §1 · **Decisions:** ADR-0003, ADR-0005, ADR-0027, ADR-0028

## Context
STORY-04.3 must deliver the SPEC-07 §2 sources surface: `GET/POST /v1/sources`,
`GET/PATCH/DELETE /v1/sources/{id}`, `POST /v1/sources/{id}/sync` and
`POST /v1/sources/{id}/test`. The story traces FR-SRC-01 (create, update, pause,
resume, delete) and FR-SRC-14 ("test connection").

Three things the endpoints appear to need do not exist yet:

- **A sources store.** There is no persistence layer for sources.
- **The connector framework** (SPEC-04 §1 `Connector.ValidateConfig`/`Test`,
  the registry) — that is EPIC-06 (STORY-06.1). "Body validated by connector"
  and the entire `/test` endpoint depend on it.
- **The job worker** (River, ADR-0005) that executes `sync_source` and
  `delete_source` jobs and performs the FR-SRC-12 cascade — that is EPIC-09.

The house rule for this situation (STORY-04.1/04.2 precedent) is: build the HTTP
layer and a real thin store for what the schema already supports, and inject the
not-yet-built pieces as seams that fail closed — do not build EPIC-06/09 work
under an EPIC-04 story.

Two facts about the existing schema shape the design:

- `sources` and `jobs` are **control-plane** tables (`schemas/control_plane.sql`;
  C-3 places the source registry in the control plane, and tenant content never
  lives there). So the endpoints operate on the control-plane pool — there is no
  `tenant.DB` and no tenant-plane connection on this path (ADR-0003).
- `jobs` already carries the partial unique index
  `jobs_one_active_sync_per_source` (`kind='sync_source' and status in
  ('queued','running')`). That index *is* the SPEC-07 §2 "409 if one already
  active" mechanism.

## Options
- **Where sources live.** (a) a tenant-plane table — rejected: it would add a
  `tenant_id` to a tenant table (violates C-1) and contradicts C-3, which puts
  the registry in the control plane; (b) the existing control-plane `sources`
  table, tenant-scoped by the resolved credential (chosen).
- **Concurrent-sync 409.** (a) a read-then-insert check (racy); (b) let the
  existing partial unique index reject the second active sync and map the unique
  violation to 409 (chosen — correct under concurrency, no new schema).
- **Enqueue.** (a) wait for EPIC-09/River; (b) write the `queued` mirror row into
  the existing `jobs` table now — the row the worker will consume — and treat the
  worker/River dispatch and the FR-SRC-12 cascade as EPIC-09 (chosen). The API's
  job *is* to enqueue; the `jobs` table is the history/mirror view (ADR-0005), so
  writing a queued row is legitimately the API side of the seam.
- **Connector validation / test.** (a) a fake/no-op connector — rejected
  (a no-op `ValidateConfig` would claim invalid configs are valid; a mock is
  forbidden by the integrity rule); (b) a narrow injected `Validator` port, nil
  until EPIC-06 (chosen): create/update run generic validation always and the
  connector's kind-specific `ValidateConfig` only when the port is wired; `/test`
  reports the not_found seam envelope until then (mirroring STORY-04.1).
- **Idempotency-Key.** (a) a new idempotency-keys store (heavy); (b) store the
  key in the `sync_source` job's `payload` and replay the active job when the
  same key recurs (chosen — no new schema; the unique index still 409s a
  *distinct* concurrent sync).
- **Credentials.** (a) accept + encrypt now — rejected as EPIC-06 STORY-06.2
  scope creep; (b) reject a `credentials` field with a 400 (chosen): failing
  closed keeps plaintext secrets off the write path (C-4) and defers the
  per-connector credential lifecycle to STORY-06.2. FR-SRC-10 ("never returned")
  is upheld regardless: no response ever includes `credentials_enc`.

## Decision
Add `internal/cp/sources`: a `Store` (PoolDB over the control-plane pool),
a `Service` (generic validation + the sync/delete/idempotency logic) with an
optional `Validator` seam, and `Handlers` speaking the SPEC-07 §1 envelope with
the tenant taken only from the resolved context (FR-ACC-03). Router routes are
appended to `New` and to the `liveRoutes()` table so the OpenAPI doc, the drift
guard and the contract tests (ADR-0028) grow with them; `api/openapi.yaml` is
regenerated by `mise run openapi`.

Concurrent-sync 409 comes from the existing partial unique index; the
Idempotency-Key is honoured via `jobs.payload`; credential handling and the
connector framework/worker are injected seams that fail closed.

## Consequences
- The whole sources CRUD surface, manual sync (with real 409 + idempotency), and
  the delete enqueue are live and e2e-tested against the real control-plane
  Postgres now — no EPIC-06/09 code was built under this story.
- `/test` returns the not_found seam envelope and create/update skip
  kind-specific config validation until EPIC-06 (STORY-06.1) wires the
  `Validator`. When it lands, wiring the port in `buildAPIServer` is the only
  change here — no HTTP-surface churn (NFR-MNT-01).
- The queued `sync_source`/`delete_source` rows this layer writes are the mirror
  rows the EPIC-09 worker (STORY-09.1/09.2/09.6) will pick up; that worker
  performs the FR-SRC-12 cascade removal of documents/chunks.
- `credentials` on create/update is a 400 until STORY-06.2; clients cannot set
  source secrets yet. No plaintext secret ever reaches the store (C-4).
- No schema/migration change: the `sources` and `jobs` tables and the unique
  index already existed, so the STORY-01.5 drift guard stays green.
