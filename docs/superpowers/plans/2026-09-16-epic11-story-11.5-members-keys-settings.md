# EPIC-11 STORY-11.5 — Members, API keys, settings pages — Implementation Plan

> **For agentic workers:** use superpowers:subagent-driven-development. Steps use `- [ ]`.

**Goal:** Let a session admin manage a tenant's **members** (roster, add by email, change role, remove), **API keys** (list, mint with a one-time secret reveal, revoke), and **settings** (embedding/llm/reranker/chunking/retrieval/rewrite) from the admin UI — over session-authenticated, tenant-scoped routes that reuse the EXISTING `MembershipService`, `APIKeyService`, and `SettingsService` (ADR-0075).

**Architecture:** Same as STORY-11.2/11.3 — mount handlers behind `RequireSession -> RequireTenantAccess(perm)` at `/admin/tenants/{tenantId}/…`; the handlers read the tenant from context. Settings handlers already exist (`internal/cp/tenants`); members/api-key handlers are thin new wrappers over the existing services. The Next UI adds three pages.

**Spec/decisions:** SPEC-02 §2 (members/keys), SPEC-02 §5 (settings), SPEC-09 §2–3, ADR-0075, ADR-0021 (api-key format), ADR-0022 (settings/dim immutability). ISSUE-0064.

## Global constraints
- Reuse `auth.MembershipService`, `auth.APIKeyService`, `tenants.SettingsService` verbatim — no CRUD logic duplicated. Only new server code: thin HTTP handlers + a `UserByEmail` lookup + route mounts + middleware wiring.
- Authz per SPEC-02 §4 (`roles.go`): reads = `PermQuery` (any member); members/keys writes = `PermManageMembers` (owner/admin); settings PATCH = `PermChangeSettings` (owner/admin). Inaccessible/unknown tenant → 404. CSRF on all mutations; none on GETs.
- Secrets: an API key's plaintext is returned ONCE by Create and never again (FR-ACC-04); List shows prefix + metadata only. Never logged (C-4).
- Go: `mise run lint` 0 new (10 baseline). Web: `npm run build` + `npx vitest run` green. Every change carries **ISSUE-0064**. No co-authored trailers.

### Task 1: Backend — user-by-email lookup, members + api-key handlers, mount all three surfaces

**Files:**
- Create `internal/cp/auth/members_handlers.go` (+ test) — `MembershipHandlers{List, Add, SetRole, Remove}` over `MembershipService`.
- Create `internal/cp/auth/apikey_handlers.go` (+ test) — `APIKeyHandlers{List, Create, Revoke}` over `APIKeyService`.
- Modify `internal/cp/auth/membership.go` (or a new `users.go`) — add `UserByEmail(ctx, email) (userID string, err error)` (needed so Add resolves an email to an existing user; ErrUserNotFound → 404 "user must sign up first"; no invite/email flow in this story).
- Modify `internal/api/router.go` — add Deps `SettingsGet/SettingsPatch`, `MemberList/MemberAdd/MemberSetRole/MemberRemove`, `KeyList/KeyCreate/KeyRevoke`, and middleware `RequireTenantChangeSettings` (PermChangeSettings) + `RequireTenantManageMembers` (PermManageMembers); mount routes. Reads reuse the existing `RequireTenantSourcesRead` (= `RequireTenantAccess(PermQuery)`; the "Sources" in the name is historical, per the STORY-11.3 note).
- Modify `internal/cli/api_server.go` — build the handlers over the existing services (the membership/apikey/settings services are already constructed for other surfaces or built here) and wire the Deps + `authz.RequireTenantAccess(auth.PermChangeSettings|PermManageMembers)`.

**Routes (all `{tenantId}` tenant-scoped):**
```
GET   /admin/tenants/{tenantId}/settings            RequireTenantSourcesRead        -> SettingsGet
PATCH /admin/tenants/{tenantId}/settings            RequireTenantChangeSettings +CSRF -> SettingsPatch
GET   /admin/tenants/{tenantId}/members             RequireTenantSourcesRead        -> MemberList
POST  /admin/tenants/{tenantId}/members             RequireTenantManageMembers +CSRF -> MemberAdd     {email, role}
PATCH /admin/tenants/{tenantId}/members/{userId}    RequireTenantManageMembers +CSRF -> MemberSetRole {role}
DELETE /admin/tenants/{tenantId}/members/{userId}   RequireTenantManageMembers +CSRF -> MemberRemove
GET   /admin/tenants/{tenantId}/api-keys            RequireTenantManageMembers      -> KeyList
POST  /admin/tenants/{tenantId}/api-keys            RequireTenantManageMembers +CSRF -> KeyCreate    {name, scopes[], expires_at?}
DELETE /admin/tenants/{tenantId}/api-keys/{keyId}   RequireTenantManageMembers +CSRF -> KeyRevoke
```
NOTE api-keys LIST is `RequireTenantManageMembers` (keys are sensitive), members LIST is `RequireTenantSourcesRead` (roster visible to any member).
